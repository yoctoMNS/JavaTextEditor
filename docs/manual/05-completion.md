# 5. コード補完

INSERTモードで、識別子の入力に合わせてコード補完ポップアップを利用できます。トリガーキーは2つあり、参照する候補の集め方が異なります。

**`.java` ファイルを編集している場合は、IntelliJ IDEA と同じ考え方の補完が働きます**（メンバー補完・シグネチャ表示・確定時の括弧/import挿入）。それ以外のファイル（C言語ファイル・ファイル名未設定のバッファなど）では、従来どおりの単語ベースの補完が働きます。

## `Ctrl+Space`（コード補完）

| 編集中のファイル | 候補の集め方 |
|---|---|
| `.java` | 下記「Javaバッファでの補完」のとおり。メンバー補完・キーワード・JDKクラス名・単語 |
| それ以外 | `WordIndex`（作業ディレクトリ配下のファイル + 現在バッファの単語）を最優先で表示し、埋まらなかった残り枠に `CompletionIndex`（JDKクラス名のみ）の候補を重複除去のうえ追加 |

## `Alt+/`（単語補完）

`WordIndex` のみを使う単語補完です（Vimの `i_CTRL-N` 相当）。JDKクラス名は候補に含まれず、**並び順もカーソルからの近接順のまま**で、IntelliJ式の並べ替えは行いません（Vim互換の挙動を保つため、ファイル種別によらず共通です）。

> 当初は `Ctrl+N` に割り当てる想定でしたが、INSERTモードの `Ctrl+N` は既にEmacs式「カーソル下移動」に確定済みのため、`Alt+/` が割り当てられています（`Ctrl+N` のカーソル下移動は維持されています）。

## Javaバッファでの補完

### メンバー補完（`obj.` の後）

`.` を打った時点で、レシーバの型が実際に持っているメソッド・フィールドだけが候補になります。プレフィックスを打っていなくても候補が開きます。

型の解決は2段構えです。

1. **即時**: 変数の宣言を近くの行から探し、リフレクションでメンバーを列挙します。キー入力に追随できる速さですが、`var`・ジェネリクスの要素型・メソッドチェーンの戻り値型までは分かりません
2. **正確**: バックグラウンドで javac に型解決させ、結果が届いた時点でポップアップの中身が差し替わります。`list.get(0).` や `var sb = new StringBuilder(); sb.` のような、宣言を読むだけでは分からない型もこちらで解決されます

同じレシーバのままプレフィックスを打ち進めている間は解決結果が再利用されるため、javacの解析は1回しか走りません。

### 候補に表示される情報

```
mth append(String str)                    StringBuilder
^   ^      ^                              ^
|   |      引数リスト                      戻り値型・フィールドの型
|   候補名（入力に一致した文字が強調表示される）
種別（cls=クラス / mth=メソッド / fld=フィールド / kw=キーワード / wd=単語）
```

### 候補の絞り込み方

前方一致だけでなく、IntelliJ IDEA と同じ次の一致も拾います（大文字小文字は区別しません）。

| 入力 | 一致する例 | 種類 |
|---|---|---|
| `subs` | `substring` | 前方一致 |
| `NPE` | `NullPointerException` | CamelCase頭文字 |
| `sb` | `stringBuilder` | CamelCase頭文字 |
| `Builder` | `StringBuilder` | 単語境界からの部分一致 |
| `acl` | `AbstractCollection` | ファジー（部分列） |

### 候補の並び順

上から順に優先されます。

1. 一致の質（完全一致 → 前方一致 → CamelCase → 単語境界の部分一致 → ファジー）
2. 近さ（ローカル変数 → メンバー → 編集中のファイル → プロジェクト → キーワード → 単語索引 → JDKクラス名）
3. 過去にその候補を選んだ回数（エディタを終了すると忘れます）
4. 上記がすべて同じなら、カーソルからの近接順

### 確定したときの動作

| 候補の種別 | 確定時の動作 |
|---|---|
| メソッド | `名前()` が挿入され、引数があればカーソルは括弧の内側に入る |
| フィールド・変数・キーワード | 名前だけが挿入される |
| クラス（JDK） | クラス名が挿入され、必要なら `import` 文がその場で挿入される（候補が1つに定まる場合のみ） |

プロジェクト内のクラスや、同名クラスが複数ある場合のimportは、その場では挿入されません。従来どおりINSERTモードを抜けた時点の自動import（複数候補があれば選択画面）で処理されます。

## 自動トリガー

INSERTモードで1文字入力するたびに、現在アクティブな補完セッションのモード（コード補完/単語のみ）を維持したまま自動的に再クエリされ、候補があれば自動的にポップアップが表示されます。明示的にキーを押さなくても入力中に候補が出る「入力しながら補完」の挙動です。`.java` バッファでは、`.` を打った直後も同様に自動で開きます。

## ポップアップ操作

| キー | 動作 |
|---|---|
| `↑` / `↓`（`Ctrl+P` / `Ctrl+N`） | 候補を選択 |
| `Tab` / `Enter` | 選択中の候補を確定挿入 |
| `Escape` | ポップアップを閉じる |

カーソル移動・改行・単語削除などの操作でもポップアップは自動的に閉じます。候補が10件を超える場合はスクロールし、右端にスクロール位置の目印が表示されます。

## インデックスの構築

- `WordIndex`・`CompletionIndex` はいずれもエディタ起動時に1回だけバックグラウンド（仮想スレッド）で構築されます。`:cd` で作業ディレクトリを変更しても再構築はされません
- ビルド中はCtrl+Space/Alt+/を押しても「補完インデックス構築中...」のメッセージが表示されるだけで、ビルド完了後に通常どおり利用できます
- `.git`/`build`/`target`/`node_modules` 等の慣例的なディレクトリと、2MBを超えるファイル・既知のテキスト拡張子以外のファイルはインデックス対象から除外されます
- メンバー補完の型解決（javac）は索引ではなくその場の解析です。プロジェクト配下の `.java` が2000ファイルを超える場合は解析を諦め、即時解決の結果だけが表示されます
