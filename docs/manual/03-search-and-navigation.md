# 3. 検索・ナビゲーション

## バッファ内文字列検索

### Emacs式インクリメンタルサーチ（`Ctrl+S` / `Ctrl+R`）

`Ctrl+S`（前方検索）・`Ctrl+R`（後方検索）は **NORMAL・INSERT両モード**で使えます。Modeは変えず、呼び出し元のモードのまま完結する疑似的なサブ状態として動作します（NORMALモードで起動すればNORMALモードのまま、INSERTモードで起動すればINSERTモードのまま）。

| キー | 動作 |
|---|---|
| `Ctrl+S` | isearchセッションが未起動なら前方検索で起動。起動中なら現在のクエリのまま次の候補（さらに後方）へ進む |
| `Ctrl+R` | isearchセッションが未起動なら後方検索で起動。起動中なら検索方向を反転し、前の候補へ進む |
| 通常文字 | クエリに1文字追加し、その場で最も近い候補へリアルタイムでカーソルを移動（1文字消すたびに再ジャンプ） |
| `Backspace` | クエリの末尾を1文字削除し、削除前にいた候補へ正確に戻る |
| `Enter` | 現在のマッチ位置にカーソルを残したままisearchを終了し、通常のNORMAL/INSERT入力に戻る |
| `Escape` | isearch開始時点のカーソル位置へ戻してから終了する |
| 上記以外のキー（矢印キー等） | 現在位置はそのままisearchを終了し、そのキーを通常のNORMAL/INSERT処理として実行する（本家Emacsと同様、未束縛キーがisearchを終了させる） |

検索対象はリテラル文字列（大文字小文字は区別しない）で、正規表現は使えません。ステータスバーには `I-search: <クエリ>`（後方検索時は `I-search backward: <クエリ>`）が表示されます。

> かつて存在した `/` によるVim式パターン入力検索（Enterで確定してから `n`/`N` で移動する方式）は、検索アルゴリズムをEmacs式に一本化するため廃止されました。自由な文字列・正規表現でその場から検索したい場合は `Ctrl+S`/`Ctrl+R` を使ってください。

### 単語検索（`*` / `#`）と `n` / `N`

Vimとの互換性のため、カーソル位置の単語を検索する `*`/`#` と、その結果を移動する `n`/`N` はNORMALモードに引き続き存在します。

| キー | 動作 |
|---|---|
| `*` | カーソル位置の単語を単語境界（`\b`）付きで下方向へ完全一致検索し、全マッチを半透明黄色でハイライト |
| `#` | カーソル位置の単語を単語境界付きで上方向へ完全一致検索 |
| `n` | 最後の `*`/`#` と同方向で次のマッチへジャンプ（末尾まで達すると先頭へ折り返す） |
| `N` | 最後の `*`/`#` と逆方向で前のマッチへジャンプ（折り返しあり） |
| `Escape` `Escape`（NORMALモードで2回連続） | 検索ハイライトを強制的にクリア（1回目のEscapeは保留中の他の多打鍵シーケンスのキャンセルのみに使われるため、ハイライトを消すには2回押す） |

カーソル位置に単語が無い場合は `No word at cursor` がステータスバーに表示されます。検索ハイライトは `*`/`#` 実行時・ファイル読み込み・上記の2回連続Escape・isearchの終了（Enter/Escape）でクリアされます（バッファ編集時には自動更新されないため、`n` を押すことで再計算されます）。`K`・`gr`・`:grep`・telescope選択など、バッファを差し替えるほぼすべての操作でも前のバッファのハイライトが残らないよう自動的にクリアされます。

`*`/`#`/`n`/`N` と `Ctrl+S`/`Ctrl+R`（isearch）は独立した検索状態を持ちます。isearchの検索文字列は `n`/`N` の移動には使われません。

## ファイル名検索・ファイル内容grep（FILESEARCHモード）

| キー | 動作 |
|---|---|
| `\f` | FILESEARCHモードへ（ファイル名検索）。プロジェクト配下のファイル名を正規表現（大文字小文字無視）で検索 |
| `\g` | FILESEARCHモードへ（ファイル内容grep検索）。プロジェクト配下のファイル内容を正規表現でgrep |

FILESEARCHモード中の操作:

| キー | 動作 |
|---|---|
| 通常文字 | 検索パターンに文字を追加 |
| `Backspace` | パターンの末尾の文字を削除 |
| `Enter` | パターンで検索を実行しNORMALモードへ戻る（結果は疑似バッファに一覧表示、`Enter` でジャンプ） |
| `Escape` | 検索をキャンセルしてNORMALモードへ戻る |

### bang（`!`）付き全ファイル検索

デフォルトの検索は `.git` / `build` / `target` / `.gradle` / `node_modules` / `.idea` / `.vscode` をスキップします。パターンの**先頭に `!` を付けて**Enterすると、これらのスキップを無視して作業ディレクトリ配下の全ファイルを対象に検索します（`!` はパターンから取り除かれます）。

```
\f!pattern    → 全ファイル対象のファイル名検索
\g!pattern    → 全ファイル対象のgrep検索
```

`gR`（後述）・`:grep!`（後述）も同じ「bang = 全ファイルスキャン」の意味を持ちます。タイムアウト（後述）とファイルサイズ上限は bang の有無に関わらず常に適用されます。

## プロジェクト全文検索（`:grep`）

COMMANDモードで `:grep <pattern>` を実行すると、作業ディレクトリ配下を正規表現で全文検索し、結果を `*grep*` 疑似バッファに一覧表示します。

| コマンド | 動作 |
|---|---|
| `:grep <pattern>` | 通常の全文検索（スキップ対象ディレクトリを除外） |
| `:grep! <pattern>` | bang付き全文検索（スキップ対象ディレクトリも含めて全ファイル検索） |

`*grep*` 疑似バッファ内では以下のキーが使えます。

| キー | 動作 |
|---|---|
| `j` / `k` | 結果行を移動 |
| `Enter` | カーソル行の結果ファイルを開き、該当行へジャンプ |
| `:e <path>` | 別のファイルを開き、grepモードを解除する |

不正な正規表現には `E: bad pattern: ...`、一致なしには `grep: no matches for /<pattern>/` を表示します。2MBを超えるファイルは全文読み込みをスキップします（巨大ファイルによるフリーズ対策）。

## 参照検索（`gr` / `gR`）とシンボル定義ジャンプ（`K` / `Shift+J`）

| キー | 動作 |
|---|---|
| `gr`（`g` の後に `r`） | カーソル位置の識別子を単語境界付きでプロジェクト全体からgrep検索し、`*grep*` 疑似バッファに一覧表示（スキップ対象ディレクトリは除外） |
| `gR`（`g` の後に `Shift+R`） | `gr` のbang版。スキップ対象ディレクトリも含めて全ファイルを検索 |

`K`（定義・ドキュメント参照ジャンプ）と `Shift+J`（ジャンプ元へ戻る）は、JDKクラス参照だけでなくプロジェクト内シンボルの定義ジャンプも兼ねます。詳細は [Java開発支援](04-java-tooling.md#定義ジャンプとドキュメント参照-k--shiftj) を参照してください。

## telescope ファジーファインダー

telescope.vim風のあいまい検索（ファジーマッチング）機能です。当初は画面中央の3ペインオーバーレイ（Prompt / Results / Preview）で表示していましたが、2026-07に「`\f`/`\g`と同じ表示方法に揃えてほしい」という要望を受けて表示方式を変更しました。現在は `\f`/`\g` と全く同じ「ヘッダ行＋結果一覧」の疑似バッファ方式で表示されます（あいまい検索・スコアリング自体は維持。プレビューペインは廃止）。

| キー | 起動する機能 |
|---|---|
| `SPC+f` | ファジーファイル検索 |
| `SPC+/` | ライブgrep |
| `SPC+b` | 開いているバッファの一覧 |

TELESCOPEモード中の操作:

| キー | 動作 |
|---|---|
| 通常文字 | クエリバッファに追加し、リアルタイムでフィルタリング |
| `Backspace` | クエリの末尾の文字を削除 |
| `Ctrl+N` / `Ctrl+P` | 候補リストを次/前へ移動（結果一覧は再構築せず、実カーソルを候補行に合わせるだけ） |
| `Enter` | 選択中の候補を開いてNORMALモードへ戻る（grep結果は該当行へジャンプ） |
| `Ctrl+D`（`SPC+b` のバッファ一覧のみ） | 選択中のバッファをバッファ一覧（`Ctrl+U`/`Ctrl+P`での切替対象・レジストリ）から削除（クローズ）する。ファイル自体やディスク上の内容には影響しない。`d`/`D`はいずれもクエリ入力（フィルタ）として扱われる |
| `Escape` | キャンセルしてNORMALモードへ戻る（元のバッファへ復元） |

ファジーマッチは連続一致+3・単語境界+2・通常一致+1・ギャップ-1のスコアリングにより降順で表示されます。クエリは画面下部のステータス行に `<title>  > <query>` の形式でリアルタイム表示され、結果一覧は `*<title>* <query> — N result(s)` ヘッダに続けてバッファ本体に描画されます。起動時の元バッファ（`*grep*`/`*file-search*` 疑似バッファ上にいた場合はその状態も含む）は退避され、`Escape` でキャンセルすると復元されます。

## 作業ディレクトリと `:cd`

`:grep`・`:rename`・ファイル名検索・telescope・FILERはすべて `WorkingDirectoryManager` が管理する単一の作業ディレクトリを基準に動作します。

| コマンド | 動作 |
|---|---|
| `:pwd` | 現在の作業ディレクトリをステータスバーに表示 |
| `:cd <path>` | 作業ディレクトリを変更（相対パスは現在の作業ディレクトリから解決、`~` 展開に対応）。成功すると自動的にFILERモードへ遷移する |
| `:mkdir <path>` | 現在の作業ディレクトリ基準でディレクトリを新規作成する。`:cd` と異なり作成先へは移動せず、実行時の作業ディレクトリに留まる |
| `:pr` | 現在の作業ディレクトリをF10/F11/F12用プロジェクトルートとして固定 |

作業ディレクトリを変更するGUIメニューは存在しません（`:cd` コマンドのみがこのエディタでの変更手段です）。

### `:cd`/`:e` のTABパス補完

COMMANDモードでコマンド入力中に `cd`/`cd <partial-path>` または `e`/`e <partial-path>` と入力した状態で `Tab` を押すと、パス名の前方一致補完が行われます。

- 候補が0件: 何もしない
- 候補が1件: その場で `commandBuffer` を補完（`:cd` はディレクトリ名の末尾に `/` を付与し、続けてTabで深掘り可能）
- 候補が2件以上: `*cd候補*` / `*e候補*` 疑似バッファに候補一覧を表示（`:e` はファイルとディレクトリの両方を候補にし、ディレクトリ名の末尾に `/` を付与）

疑似バッファ内では `Enter` で選択・補完を確定してCOMMANDモードの入力を再開し、`q` でキャンセルして元のバッファと入力途中のコマンド文字列を復元します。

## FILERモード（ディレクトリブラウザ）

`:cd <path>` が成功すると自動的にFILERモードへ遷移し、新しい作業ディレクトリの内容（ディレクトリ優先・各グループ内はアルファベット順）を表示します。当初は3ペインオーバーレイ（プレビュー欄付き）で表示していましたが、telescopeと同時期（2026-07）に「`:cd` でディレクトリ移動している間もオーバーレイ画面が表示されてしまう」という指摘を受け、`\f`/`\g`/telescopeと同じ疑似バッファ方式（`*filer* <作業ディレクトリ> — N件` ヘッダ＋エントリ一覧をバッファに直接描画、ディレクトリ名末尾に `/` を付与）に統一しました。プレビュー欄は廃止されています。選択中の項目は専用ハイライトではなく実際のテキストカーソルで示されます。

| キー | 動作 |
|---|---|
| `Ctrl+N` / `Ctrl+P` | 選択項目を下/上へ移動 |
| `Enter` | ディレクトリを選択した場合はそのディレクトリへ移動して一覧を更新（ドリルダウン）。ファイルを選択した場合はそのファイルを開いてNORMALモードへ戻る |
| `/` | FILER内検索サブモードへ入る |
| `Esc` | FILERモードを終了してNORMALモードへ戻る |
| `:`/`;` | COMMANDモードへ入り、`:cd`/`:e`/`:pr`/`:mkdir` 等をそのまま実行できる（`;` はNORMAL/VISUALモードと同じくVim式の `:` エイリアス）。`:cd`/`:e` は実行後FILERを抜けて対象を開くが、`:pr`/`:mkdir` はバッファを操作しないため実行後もFILERに留まり一覧を再読み込みする |

FILER内検索サブモード（`/` 押下後）:

| キー | 動作 |
|---|---|
| 通常文字 | クエリに追加し、大文字小文字無視の部分一致でリアルタイムにフィルタリング |
| `Backspace` | クエリを1文字削除して再フィルタリング |
| `Ctrl+N` / `Ctrl+P` | フィルタ後の候補を移動 |
| `Enter` | 選択（ディレクトリ移動 or ファイルを開く） |
| `Esc` | 検索サブモードのみをキャンセルし、フィルタなしの一覧に戻る（FILERモード自体は継続） |

> 一覧の先頭には親ディレクトリへ移動する `..` エントリが表示されます（ファイルシステムのルートで親が無い場合を除く）。選択して `Enter` で上の階層へ移動できます。

## バッファ履歴の切り替え（`Ctrl+U` / `Ctrl+P`）

NORMALモードの `Ctrl+U` は「前のバッファへ切り替え」、`Ctrl+P` は「次のバッファへ切り替え」に割り当てられています。現在のバッファの種類によって挙動が異なるハイブリッド方式です。

- **ファイルを開いている通常のバッファの場合**（`:e`・telescope・FILER等いずれかの経路で開いたファイル）: これまでに開いたファイルの一覧（バッファレジストリ）を `:bprev`/`:bnext` と同じ意味論で循環します。切替先のファイルは**毎回ディスクから読み直す**ため、未保存の編集内容は保持されません。また切替後はカーソルが常に先頭（0行目）に戻ります。開いているファイルバッファが自分1件のみの場合は「他に開いているファイルバッファがありません」と表示されるだけで何も起きません。
- **ファイルパスを持たない疑似バッファの場合**（`:tutor`・`:enew` 等）: 従来どおりバッファ履歴のスナップショット方式にフォールバックします。こちらはテキスト内容とカーソル位置をそのまま保持したまま行き来できます。`:tutor` でチュートリアルを開いた後に元のバッファへ戻る場合などに使えます。

## 検索処理のタイムアウトについて

`K`（[Java開発支援](04-java-tooling.md)参照）・`gr`/`gR`・`:grep`/`:grep!` によるプロジェクト全体検索は、対象ファイル数が多い作業ディレクトリ（例: ホームディレクトリ全体）で無制限にUIをフリーズさせないよう、最大1.5秒のタイムアウトが設定されています。タイムアウトした場合は検索を打ち切り、`K` はJDK側のフォールバック検索に切り替わり、`gr`/`:grep` は "search timed out" を表示します。
